# cdalkit

## 0.1.6

### Patch Changes

- `cdalkit validate` and `cdalkit codegen` use the contract kinds registered in `cdal.config.mjs` (built-in, CDAL Pro or custom). They used to always run only the three built-in kinds, so custom kinds were never validated or generated.

## 0.1.5

### Patch Changes

- `cdalkit pro install` clones CDAL Pro from the `cdalkit` GitHub organization (Polar only grants repository access on organization repositories).

## 0.1.4

### Patch Changes

- guard-paths fails closed for a role declared by a CDAL role hook (e.g. `guard-paths implementer`) that is missing from `cdal.config.mjs`: every write is denied with a message explaining how to configure it. Sessions and built-in subagents without a declared role keep the previous behavior (protected paths only). `cdalkit pro install` replaces role files generated by `cdalkit sync` while keeping user-owned files.
- Updated dependencies
  - @cdal/core@0.1.1
  - @cdal/adapters@0.1.3
  - @cdal/audit@0.1.1
  - @cdal/kinds@0.1.1

## 0.1.3

### Patch Changes

- `cdalkit sync` never overwrites or reports drift for files marked `<!-- cdal:preserve -->`, so CDAL Pro roles and hand-tuned agent files survive a sync.
- Updated dependencies
  - @cdal/adapters@0.1.2

## 0.1.2

### Patch Changes

- Add `cdalkit pro install`, which installs CDAL Pro content (agent roles, templates, presets) from the private cdal-pro repository into a project, as listed in its `pro.manifest.json`.

## 0.1.1

### Patch Changes

- Fix Claude Code hook wiring: `.claude/settings.json` and agent role frontmatter now use the Claude Code hooks schema (matcher groups with `type: command` handlers). The previous flat format was ignored by Claude Code, so the CDAL gates never ran. Run `npx cdalkit sync` to regenerate existing projects. `cdalkit doctor` now detects the legacy format.
- Updated dependencies
  - @cdal/adapters@0.1.1
